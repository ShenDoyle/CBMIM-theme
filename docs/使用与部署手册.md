# CBMIM theme · 使用与部署手册

> 这份手册讲两件事：**这个主题怎么用**、**站点（cbm.im）怎么部署**。
> 所有命令都可以直接复制执行；Windows 下用 Git Bash / PowerShell 均可。

---

## 一、先弄清这套东西的组成

| 仓库 | 角色 | 谁在用 | 能不能手改 |
|---|---|---|---|
| `ShenDoyle/CBMIM-theme` | **主题仓**（本仓） | 站点通过 npm 依赖 `hexo-theme-cbmim: github:ShenDoyle/CBMIM-theme#main` 引用 | ✅ 改主题只在这里改 |
| `ShenDoyle/Blog-cbmim` | **源码仓** | Hexo 站点源码、`source/` 内容、`scripts/`、`tools/`、GitHub Actions | ✅ 改站点/脚本/文章在这里改 |
| `ShenDoyle/ShenDoyle.github.io` | **产物仓** | GitHub Pages 的源站，绑 CNAME `cbm.im` | ❌ 由部署强推覆盖，手改必丢 |
| Vercel | **前置加速层** | 不参与构建，只是给 Pages 套一层 CDN 缓存 | — |
| Notion | **内容后台** | 文章、独立页面、主题设置 | ✅ 日常写作都在这里 |

**为什么源码和产物必须分成两个仓？** 部署用的是 `git push --force`（hexo-deployer-git 的行为）。如果源码和产物放在同一个仓，第一次部署就会把源码整个覆盖掉。

**判断"线上到底是不是最新"的唯一可靠指标**：看产物仓 `ShenDoyle.github.io` 的最后一次提交时间。不要看页面响应头 —— `cbm.im` 的响应头是 `Server: Vercel`（前置缓存），而 `shendoyle.github.io` 那次 301 的 `Server: GitHub.com` 才说明 Pages 是源站。

## 二、日常发布：三种触发方式

内容改完，等它自己上线即可。不需要在本地做任何事。

| 触发方式 | 什么情况下用 | 怎么触发 |
|---|---|---|
| **push 到 main** | 改了主题、脚本、配置、手工文章 | `git push origin main`，几秒后自动开始构建 |
| **每 6 小时定时** | 只在 Notion 里改了文章 | 无需操作，等待即可（**内容无变化时会跳过构建**，这是刻意设计） |
| **手动 Run workflow** | 想立刻上线，或调试 | Actions →「Notion 同步并发布」→ Run workflow |

手动触发的两个开关：

- `dry_run: true` → 只预览同步结果，**不写文件、不部署**（排查用）
- `force: true` → 忽略增量，26 篇文章全部重新生成

> ⚠️ 定时触发时**只有 Notion 内容有变化才会部署**。所以"我在本地改了脚本，等 6 小时自己上线"是**不会发生**的 —— 这种改动必须靠 push 触发（这也是工作流后来专门加上 `push` 触发的原因）。

## 三、完整的可执行方案

### 3.1 本机准备（只做一次）

```bash
# 需要 Node 22+ 和 git；确认 SSH 已能推 GitHub
node -v          # v22.x
ssh -T git@github.com   # 应回显 Hi ShenDoyle!
```

### 3.2 本地预览站点（改样式 / 改脚本时用）

```bash
git clone git@github.com:ShenDoyle/Blog-cbmim.git && cd Blog-cbmim
npm ci                 # 严格按 package-lock 安装（含从 GitHub 拉主题）
npx hexo clean
npx hexo generate      # 产物在 public/
npx hexo server        # http://localhost:4000
```

> `hexo server` 用的是内存里的构建结果，**它不会读你手改的 `public/` 文件**。想直接看 `public/` 产物，另开一个静态服务：
> `python -m http.server 4100 --directory public`

### 3.3 发布（最常用）

```bash
# 方式一：在 Notion 改完文章，什么都不用做（等 6 小时），或去 Actions 手动 Run workflow
# 方式二：改了代码/主题/配置
git add -A && git commit -m "说明这次改了什么、怎么验证的" && git push origin main
# → push 本身就会触发构建 + 部署，不需要再点任何按钮
```

### 3.4 改主题的正确姿势

主题是 npm 依赖（`github:ShenDoyle/CBMIM-theme#main`），**不要**在站点仓里改 `node_modules/hexo-theme-cbmim` —— 下次 `npm ci` 就没了。

```bash
# 1) 在主题仓改
cd CBMIM-theme && git checkout -b fix/xxx
# …改…
git commit -m "fix(xxx): …" && git push origin fix/xxx   # 合并到 main

# 2) 回站点仓更新依赖锁定并发布
cd ../anviyu
npm update hexo-theme-cbmim        # 或 npm install hexo-theme-cbmim@github:ShenDoyle/CBMIM-theme#main
npx hexo clean && npx hexo generate   # 本地确认渲染正常
git add package.json package-lock.json && git commit -m "chore(theme): 升级主题到 <sha>" && git push
```

> ⚠️ **主题 `package.json` 的 `version` 必须保持 `1.7.1` 不动**：主题里 `scripts/events/cdn.js` 用它拼 CDN 路径（`...@<version>/...`），改了会导致 CDN 资源 404。

### 3.5 回滚

```bash
# 站点侧回滚（内容或脚本改坏了）
git revert <坏的提交> && git push origin main

# 主题侧回滚（主题改坏了）
cd CBMIM-theme && git log --oneline        # 找到上一个正常的 sha
cd ../anviyu && npm install hexo-theme-cbmim@github:ShenDoyle/CBMIM-theme#<正常sha>
git add package.json package-lock.json && git commit -m "revert(theme): 回退主题到 <sha>" && git push

# 应急：GitHub 上把产物仓回滚（线上立刻恢复旧版本，但下次部署会再覆盖）
# ShenDoyle.github.io → commits → 找到正常那次 → Revert
```

### 3.6 如果发布失败

先看这一步是不是被跳过，再看具体哪一步红：

```bash
# 用公开 API 直接读步骤级结果（仓库是 public，不需要登录、不需要 gh CLI）
curl -s "https://api.github.com/repos/ShenDoyle/Blog-cbmim/actions/runs?per_page=1"
curl -s "https://api.github.com/repos/ShenDoyle/Blog-cbmim/actions/runs/<run_id>/jobs"
```

| 红的步骤 | 大概率原因 | 处理 |
|---|---|---|
| 凭据预检 | 缺 `NOTION_TOKEN` / `NOTION_DATABASE_ID` / `DEPLOY_KEY` | 补 Secrets（Settings → Secrets and variables → Actions） |
| 安装依赖 | 拉主题失败 | 确认 `ShenDoyle/CBMIM-theme` 是 public；必要时把 lock 里的 `git+ssh://` 改成 `git+https://` |
| 同步 Notion | token 失效 / 页面未授权给 Integration | 重新生成 integration token；Notion 里把「CBMIM 博客」页面「连接」给该 Integration |
| 发布到 GitHub Pages | Deploy Key 没有写权限，或加错了仓库 | 产物仓 Settings → Deploy keys，确认 `cbmim-blog-actions` 勾了 **Allow write access** |
| 构建站点 | 抓豆瓣/追番超时，或标签语法写错 | 工作流自带一次重试；标签问题看下面第七节 |

## 四、配置都在哪

| 文件 / 位置 | 管什么 | 说明 |
|---|---|---|
| 站点仓 `_config.yml` | 站点基础 + 部署目标 | `theme: cbmim`、`deploy:`（产物仓 + 分支）。**不要手改 deploy 段** |
| 站点仓 `_config.cbmim.yml` | 主题配置的覆盖层 | 近 500 项主题配置在这里（Hexo 7 的 `_config.<theme>.yml` 机制）。**这是"默认层"** |
| Notion「⚙️ 站点设置」库 | 主题配置的覆盖层（上层） | 一行一个键；**值留空 = 不覆盖**；勾「启用」+ 值非空才生效；构建期合并到 `_config.cbmim.yml` 之上 |
| 站点仓 `.env`（已 gitignore） | 本地同步用的令牌 | `NOTION_TOKEN`、`NOTION_DATABASE_ID` |
| 仓库 Secrets | CI 用的令牌 | `NOTION_TOKEN`、`NOTION_DATABASE_ID`、`DEPLOY_KEY` |
| 站点仓 `source/_data/site-settings.yml` | 由 Notion 设置库生成的产物 | **自动生成，别手改**（git 里可追溯） |

配置优先级：**Notion 设置库 > `_config.cbmim.yml` > 主题默认 `_config.yml`**。

## 五、主题自带的可用标签（速查）

写文章时按主题的**真实签名**写，别照搬其他主题的语法。

| 用途 | 写法 |
|---|---|
| 提示块 | `{% note success %}…{% endnote %}`（success / warning / danger） |
| 折叠 | `{% folding 标题 %}…{% endfolding %}` |
| 复选 | `{% checkbox checked, 文字 %}` |
| 按钮组 | `{% btns %}` + `{% cell 文字, 链接URL, 图片URL %}` + `{% endbtns %}` |
| 站点卡片 | `{% sitegroup %}` + `{% site 标题, url=…, screenshot=…, avatar=…, description=… %}` + `{% endsitegroup %}` |
| 时间线 | `{% timeline 标题 %}` + `<!-- timeline 子项 -->` + `{% endtimeline %}` |
| 标签页 | `<!-- tabs 组名 -->` + `<!-- tab 标题 -->…<!-- endtab -->` + `<!-- endtabs -->` |
| 图廊 | `{% gallery %}![alt](url){% endgallery %}` |
| 行内 | `{% kbd Ctrl %}`、`{% u 下划线 %}`、`{% emp 着重 %}`、`{% wavy 波浪线 %}`、`{% label 文本 blue %}`、`{% span 文本, red %}` |

> 签名都在主题仓 `scripts/tag/*.js` 里，拿不准就看一眼源码，比猜快。

## 六、封面规则（当前定稿）

| 项 | 规则 |
|---|---|
| 封面图 | 最佳 **1600×700（16:7）** webp、≤300KB；留空 → 主题自带默认封面图 |
| 小字 | 固定 `CBM.IM`（品牌署名，不可配置；`封面副标题` 字段已弃用） |
| 大字 | 封面标题。单行放不下会**自动缩排**；缩到可读下限仍放不下 → 回退 `CBM.IM` |
| 小卡 | 容器宽 < 300px（轮播 / 侧栏 / 置顶小卡）**只显示分类** |
| 蒙版 | 0~1 或百分数；留空默认 0.46；`0` = 不加 |
| 模糊框 | 严格等比复刻设计稿 554×162（圆角 20/554、内边距 20.75/554、字号 58/554 都按卡片宽等比）；装不下是**加宽**，不改比例 |
| 文章顶图 | 不叠蒙版、不叠文字，只保留背景图 |
| 图片兜底 | **不做任何兜底**：没配封面用主题默认图，破图走主题自身 onerror |

## 七、排错手册（都是真实踩过的）

| 症状 | 根因 | 处理 |
|---|---|---|
| 本地怎么改都不生效，线上停在旧版本 | 触发条件只写了"定时 + 内容变化"，源码改动不触发部署 | 工作流 `on:` 要有 `push: branches: [main]`，并给 job 加 `if: github.actor != 'github-actions[bot]'` 防环 |
| 整站封面渲染成渐变 | 把主题的懒加载占位图 `loading.webp` 当成了"没配封面" | 占位图与默认封面图必须分开判断 |
| 大字末尾莫名出现省略号 | `pangu.js`（盘古之白，主题全站开启）往文字节点前塞了空格 | 给文字卡片挂 `g_editable="true"`，pangu 的忽略判断会整棵跳过 |
| 标题判定"永远放不下" | 用 `scrollWidth` 判断宽度：文字比容器窄时它返回容器宽度 | 用 `Range.getBoundingClientRect().width` 量文字本身；并给文字元素 `width:100%`（flex 列里否则会收缩成文字宽度） |
| 按钮链接是坏的、图标是外部 CDN 的默认图 | `{% cell %}` 传了 Markdown 链接语法 `[文字](链接)` | 传裸 URL：`{% cell 文字, https://…, 图片URL %}` |
| 站点卡片 href 与图片双空、渲染出破图 | `{% site %}` 用了位置参数 | 只认具名参数：`url= / screenshot= / avatar= / description=` |
| 标签参数里的 URL 又变成 `[url](url)` | Notion 自动把裸 URL 美化成链接 | 同步脚本的 `unwrapTagLinks()` 会把标签片段内的自链接解包（已内置） |
| 文章里的图上线一小时后全挂 | 直接引用了 Notion 的签名临时链接 | 让同步脚本落地到 `source/img/cbmim/<slug>/`（Notion 图床的图会自动落地，外链原样保留） |
| 改了 Notion 但同步说"跳过" | 增量同步按 `lastEditedTime` 判断 | 用 `npm run notion:sync -- --force --only <slug>` 强制重跑 |
| `--only` 传 slug 匹配不到 | 早期只支持页面 ID | 已修：现在支持 `<slug\|pageId>` |

## 八、改完必做的验收清单

```bash
npx hexo generate 2>&1 | tail -3        # 构建无 ERROR
grep -c "" public/index.html            # 首页非空
npx hexo server                          # 目视：首页大卡、轮播、侧栏、文章页
```

- [ ] 构建产物里首页、文章页都不是 0 字节
- [ ] 封面：大卡显示「标题 + CBM.IM」，小卡显示分类
- [ ] 文章页：按钮可点、卡片有图、图廊正常
- [ ] `git push` 后，产物仓出现新的 `Site updated: …` 提交
- [ ] 线上访问 `https://cbm.im/<文章路径>/` 返回 200
